This page covers MCP tool loading, timeouts, tagged task lists and the state file. For models and environment variables, see the [Configuration reference](/configuration).

## MCP tool loading

The `TASKGRAPH_TOOLS` environment variable controls which tools the TaskGraph MCP server loads, so you can trade features for context.

- **`core`** (default, alias `lean`): 7 essential tools. `get_tasks`, `next_task`, `get_task`, `set_task_status`, `add_note`, `parse_prd`, `expand_task`.
- **`standard`**: 16 tools. Core plus `update_subtask`, project initialization, complexity analysis, `dependency_analysis`, `expand_all`, subtask and task add/remove.
- **`all`**: every tool, including dependencies, tags, `research` and scope up/down. `all` gives the MCP host full project control. Prefer `core` or `standard`.
- **Custom list**: comma-separated tool names, for example `"get_tasks,next_task,set_task_status"`.

Set it in the `env` block of `.mcp.json` (recommended):

```json
{
  "mcpServers": {
    "taskgraph-ai": {
      "command": "npx",
      "args": ["-y", "taskgraph-ai"],
      "env": { "TASKGRAPH_TOOLS": "standard" }
    }
  }
}
```

Or when registering the server with Claude Code:

```bash
claude mcp add taskgraph-ai --scope user \
  --env TASKGRAPH_TOOLS="core" \
  -- npx -y taskgraph-ai
```

Behavior:

- When `TASKGRAPH_TOOLS` is unset or empty, `core` is used.
- An unknown tier (such as `standart`) or any unknown name in a custom list stops the server with exit code 1 and an error on stderr naming the unknown entries. It does not fall back to another set of tools.
- If a tool fails to register, the server also exits with code 1 instead of starting without it.
- Values are case-insensitive.

## MCP timeouts

Long-running AI operations such as `parse_prd`, `expand_task`, `research` and `analyze_project_complexity` can take 2 to 5 minutes, which exceeds the default 60-second MCP timeout. Add a `timeout` (in seconds, 1 to 3600) to the server entry in `.mcp.json`:

```json
{
  "mcpServers": {
    "taskgraph-ai": {
      "command": "npx",
      "args": ["-y", "taskgraph-ai"],
      "timeout": 300
    }
  }
}
```

If you still see `MCP request timed out after 60000ms`, check that `timeout` is present, restart Claude Code, and try `600` for very large operations.

## AI call timeout

TaskGraph gives up on an AI request that has not answered after 10 minutes. When `parse-prd` streams its tasks, the same limit is the longest it waits between two parts of the stream, so a long PRD can stream for longer as long as tasks keep arriving. A request cut off this way fails with "The AI call timed out"; the limit counts clock time, so a computer that slept during the request can hit it, and running the command again is enough. Set `TASKGRAPH_AI_TIMEOUT_MS` (milliseconds) to change it, for example `TASKGRAPH_AI_TIMEOUT_MS=1200000` for 20 minutes. Values above about 24 days are capped there.

## Loop iteration timeout

`taskgraph loop` stops a Claude Code run that has not finished after 60 minutes, together with the processes it started, and counts it as a failed iteration; three failed iterations in a row end the loop. Set `TASKGRAPH_LOOP_TIMEOUT_MS` (milliseconds) to change it, for example `TASKGRAPH_LOOP_TIMEOUT_MS=7200000` for two hours. Values above about 24 days are capped there. With `loop --parallel` the same limit applies to each task's Claude Code process: one that runs past it is stopped and marked failed, its worktree is kept and its claim released.

## Tagged task lists

Tags keep separate task lists for branches, features or experiments.

```json
"global": {
  "defaultTag": "master"
}
```

- **`defaultTag`**: the tag used when none is specified (default `master`).
- **Branch-based tags:** `taskgraph tags add <name> --from-branch` creates a tag named after the current git branch. Tags are never switched automatically; you decide when to create and use them.

## State file

`.taskgraph/state.json` tracks runtime information for the tag system:

```json
{
  "currentTag": "master",
  "lastSwitched": "2025-06-11T20:26:12.598Z",
  "migrationNoticeShown": true
}
```

- **`currentTag`**: the active tag
- **`lastSwitched`**: when the tag last changed
- **`migrationNoticeShown`**: whether the one-time tag-system notice was displayed

TaskGraph manages this file; do not edit it by hand. It's per-machine, so `taskgraph init` adds it to `.gitignore`: two people on different tags don't conflict.

When the file is missing, `master` is current. When it can't be read or saved, for example after a merge left conflict markers in it, commands fail and name the file instead of quietly using `master`. Fix it, or delete it: it holds only the current tag and branch-tag mappings.
