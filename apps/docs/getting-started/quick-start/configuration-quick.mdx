TaskGraph needs no API keys. It runs on your signed-in Claude Code, so the only thing to choose is which Claude models to use.

## Choose your models

TaskGraph has three model roles: **main**, **research** and **fallback** (used if either of the others fails). The available models are `opus`, `sonnet` and `haiku`.

```bash
taskgraph models                       # view the current configuration
taskgraph models --setup               # interactive setup
taskgraph models --set-main sonnet
taskgraph models --set-research opus
taskgraph models --set-fallback haiku
```

In Claude Code you can also say `Change the main model to opus`.

## What else can be configured?

Settings live in `.taskgraph/config.json`. Use `taskgraph models` to change models rather than editing the file by hand.

<Accordion title="View configuration options">

### Models
- Role-based model setup: `main`, `research`, `fallback`
- `modelId` per role: `opus`, `sonnet` or `haiku`
- `maxTokens` and `temperature` per role

### Global settings
- `logLevel`: logging verbosity
- `debug`: enable debug mode
- `projectName`: name of your project
- `defaultTag`: default tag for task grouping
- `defaultSubtasks`: number of subtasks to auto-generate
- `defaultNumTasks`: number of tasks to generate from a PRD
- `defaultPriority`: priority for new tasks
- `responseLanguage`: language for generated content

### Claude Code settings
- `claudeCode`: optional settings passed to Claude Code, including per-command overrides

</Accordion>

<Tip>
Control how many MCP tools are loaded with the `TASKGRAPH_TOOLS` environment variable (`core`, `standard`, `all` or a comma-separated list). See the [MCP tools documentation](/capabilities/mcp).
</Tip>
