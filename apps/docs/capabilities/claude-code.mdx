TaskGraph runs every AI operation through the Claude Code CLI. There are no provider accounts and no API keys to manage. This page covers authentication, models and the advanced Claude Code settings.

## Authentication

TaskGraph uses whatever sign-in Claude Code already has.

1. Install [Claude Code](https://docs.claude.com/en/docs/claude-code) and run `claude` once to sign in.
2. That is all. `taskgraph` commands and the MCP server now work.

Optional overrides, in the order TaskGraph considers them:

| Variable | When to use it |
| --- | --- |
| `CLAUDE_CODE_API_KEY` | Bill TaskGraph's calls to a specific Anthropic API key. When set it is used exclusively. |
| `CLAUDE_CODE_OAUTH_TOKEN` | Headless environments such as CI or containers. Create a token with `claude setup-token`. |

When neither is set, TaskGraph withholds `ANTHROPIC_API_KEY` from Claude Code so that Claude Code uses its own sign-in. See [Authentication](/getting-started/api-keys).

## Models

Each of the three roles (`main`, `research`, `fallback`) uses `opus`, `sonnet` or `haiku`:

```bash
taskgraph models --set-main sonnet
taskgraph models --set-research opus
taskgraph models --set-fallback haiku
taskgraph models --setup
```

Or edit the roles in `.taskgraph/config.json`:

```json
{
  "models": {
    "main": { "provider": "claude-code", "modelId": "sonnet", "maxTokens": 64000, "temperature": 0.2 },
    "research": { "provider": "claude-code", "modelId": "opus", "maxTokens": 32000, "temperature": 0.1 },
    "fallback": { "provider": "claude-code", "modelId": "sonnet", "maxTokens": 64000, "temperature": 0.2 }
  }
}
```

The research role is restricted to web search and fetch. It cannot read or change your files and has no shell.

## Structured outputs

Commands that generate structured data (`parse-prd`, `add-task`, `expand`, `update`, `update-task`, `analyze-complexity`) use Claude Code's native structured output support. Responses are constrained to the expected schema, so there are no JSON parsing retries.

## Advanced settings

Claude Code settings can be set globally in the `claudeCode` section of `.taskgraph/config.json`, or per command in `commandSpecific`. Command-specific settings override global ones.

```json
{
  "claudeCode": {
    "maxTurns": 5,
    "customSystemPrompt": "You are a helpful assistant focused on code quality",
    "appendSystemPrompt": "Always follow coding best practices",
    "permissionMode": "default",
    "allowedTools": ["Read", "LS"],
    "disallowedTools": ["Write", "Edit"],
    "mcpServers": {
      "mcp-server-name": {
        "command": "npx",
        "args": ["-y", "mcp-serve"]
      }
    }
  },
  "commandSpecific": {
    "parse-prd": {
      "maxTurns": 10,
      "customSystemPrompt": "You are a task breakdown specialist"
    },
    "analyze-complexity": {
      "maxTurns": 3,
      "appendSystemPrompt": "Focus on identifying bottlenecks"
    }
  }
}
```

| Setting | Purpose |
| --- | --- |
| `maxTurns` | Maximum conversation turns in a single request. Useful for complex multi-step operations. |
| `customSystemPrompt` | Replaces Claude Code's system prompt to specialize behavior. |
| `appendSystemPrompt` | Adds standards or context to the system prompt. |
| `permissionMode` | One of `default`, `acceptEdits`, `plan` or `bypassPermissions`. |
| `allowedTools`, `disallowedTools` | Restrict tools, for example for read-only analysis. |
| `mcpServers` | Extra MCP servers available to Claude Code during TaskGraph operations. |
| `pathToClaudeCodeExecutable` | Path to the `claude` executable if it is not on your `PATH`. |

See the [Claude Code settings documentation](https://docs.claude.com/en/docs/claude-code/settings) for the meaning of each value.

## Notes

- Claude Code does not report usage costs, so cost shows as 0 in telemetry.
- `temperature` and `maxTokens` are not supported by the Claude Code CLI and may be ignored.

## Troubleshooting

### "Claude Code CLI not available"

- Install it with `npm install -g @anthropic-ai/claude-code` and make sure `claude` is on your `PATH`.
- Verify it works by running `claude --help`.

### Authentication failures

- Run `claude` and sign in again.
- In CI or containers, run `claude setup-token` and pass the result as `CLAUDE_CODE_OAUTH_TOKEN`.

### Unknown model

Use one of `opus`, `sonnet` or `haiku`. Run `taskgraph models` to see the current configuration.
