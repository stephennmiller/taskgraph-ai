# AI Usage Telemetry Integration

This document outlines the standard pattern for capturing, propagating, and handling AI usage telemetry data (cost, tokens, model, etc.) across the TaskGraph stack. This ensures consistent telemetry for both CLI and MCP interactions.

## Overview

Telemetry data is generated by tm-core's `AiService` ([`ai-service.ts`](../../packages/tm-core/src/modules/ai/ai-service.ts)) and then passed upwards through the calling functions.

- **Data Source**: `AiService` (`generateText`, `generateObject`, `streamText`, `streamObject`), built with `new AiService(new AiConfig(configManager).toHost())`, returns an object like `{ mainResult: AI_CALL_OUTPUT, telemetryData: TELEMETRY_OBJECT }`.
- **`telemetryData` Object Structure**:
  ```json
  {
    "timestamp": "ISO_STRING_DATE",
    "userId": "USER_ID_FROM_CONFIG",
    "commandName": "invoking_command_or_tool_name",
    "modelUsed": "ai_model_id",
    "providerName": "ai_provider_name",
    "inputTokens": NUMBER,
    "outputTokens": NUMBER,
    "totalTokens": NUMBER,
    "totalCost": NUMBER, // e.g., 0.012414
    "currency": "USD" // e.g., "USD"
  }
  ```

## Integration Pattern by Layer

The key principle is that each layer receives telemetry data from the layer below it and passes it to the layer above it, or displays it in the case of the CLI.

### 1. tm-core services (`packages/tm-core/src/modules/tasks/services/`)

A service that calls `AiService` passes `commandName` (e.g., `add-task`, `expand-task`) and `outputType` (`cli` or `mcp`) in the params, uses `response.mainResult`, and **returns `response.telemetryData` in its result** (see `research.service.ts`). Services print nothing.

### 2. MCP Tools (in `apps/mcp/src/tools/`)

These are the exposed endpoints for MCP clients. A tool calls a tm-core method, whose result carries the `telemetryData` of its AI call, and puts that `telemetryData` in the reply's `data` next to the result (see `apps/mcp/src/tools/tasks/research.tool.ts`).

- **Example Snippet**:
  ```typescript
  execute: withToolContext(
    async (args: z.infer<typeof SomeAiActionSchema>, context: ToolContext) =>
      replyWith(args, context, 'Error running some_ai_action', async () => {
        const result = await context.tmCore.tasks.someAiAction(args.id, {
          tag: args.tag
        });
        return {
          tag: result.tag,
          data: {
            operationSpecificData: result.actionData,
            telemetryData: result.telemetryData
          }
        };
      })
  )
  ```
- `replyWith` (and `handleApiResult` under it) put `data` in the reply unchanged, so the client gets `{ data: { ..., telemetryData }, version, tag }`.

### 3. CLI Commands (`apps/cli/src/commands/`)

A command calls the tm-core method and, in text output, prints `formatUsageLine(result.telemetryData)` (`apps/cli/src/ui/formatters/usage-formatters.ts`), muted, on its own line after the main output (see `research.command.ts`).

## Summary Flow

1.  **`AiService`**: Generates `telemetryData` and returns `{ mainResult, telemetryData }`.
2.  **tm-core service**: Uses `mainResult` and returns `{ ...operationSpecificData, telemetryData }`.
3.  **MCP Tool**: Replies `{ data: { operationSpecificData, telemetryData }, version, tag }` through `replyWith` or `handleApiResult`.
4.  **CLI Command**: Prints `formatUsageLine(telemetryData)` in text output.
